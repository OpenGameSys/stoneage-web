# 石器时代 H5 重制：架构设计

目标：用现有客户端资源和原版服务端数据（`h5/gamedata`，取自 `serv/bin/gmsv/data` 的 map/ 与 npc/），按原客户端、原服务端的逻辑语义，
重新设计实现一个 HTML5 客户端和一个 Go 服务端。不兼容原版线路协议，也不兼容原版 Windows 客户端。

## 1. 总体结构

```
浏览器 (TypeScript + WebGL2)
   │  WebSocket，JSON 消息（定义见 proto/messages.json，生成 Go/TS 代码）
   ▼
Go 服务端（单进程）
   ├─ net      连接、会话、限速
   ├─ auth     账号注册/登录（PBKDF2）
   ├─ world    世界协程：移动校验、视野同步、传送、聊天、NPC、战斗流程、道具与宠物（见 CLAUDE.md 的目录说明）
   ├─ battle   回合制战斗规则核心（纯逻辑，可注入随机数）
   ├─ data     读取原版数据：地图、通行、传送、NPC、道具、敌人与技能、咒术、骑宠对照表
   └─ store    SQLite（账号、角色、道具、宠物、任务旗标等）；接口抽象，可换 MySQL/PostgreSQL
静态资源：h5/assets（图集、动画、音频，由 tools/asset-export 导出）
```

## 2. 数据来源与语义

| 数据 | 原版文件 | 语义来源 |
|---|---|---|
| 地图 | `data/map/**/<楼层号>`：`LS2MAP` + 楼层号(BE u16) + 显示名[32] GBK `名字|调色板` + 宽、高(BE u16) + 地块[宽×高](BE u16) + 物件[宽×高](BE u16) | `gmsv/map/readmap.c MAP_readMapOne` |
| 通行属性 | `data/map/mapset.txt`：`图号 ? ? walkable haveheight defence …`（第 4 列起依次为 `MAP_confentries`） | `readmap.c MAP_readMapConfFile`、`map_deal.c MAP_walkAbleFromPoint` |
| 传送点 | `data/map/mapwarp.txt`：`类型:?:楼层,x,y:目标楼层,x,y:?`；以及 NPC `enemy=npcgen_warp|楼层|x|y` | `map_warppoint.c`、`npc/npc_warp*.c` |
| NPC 摆放 | `data/npc/**/*.create`：`floorid / borncenter=x,y,w,h / dir / graphicname / name / enemy=类型|参数` | `npcgen` |
| 出生点 | 四个村庄长老：`1006(15,22)` `2006(20,16)` `3006(21,16)` `4006(14,20)` | `char/char_data.c elders[]` |
| 玩家形象 | `100000 + 20k + 5j`，k = 0..11，j = 0..3 | `char_data.c CHAR_playerImageNumber` |

通行判定照服务端：取格子上的地块和物件的 `walkable`：
- 物件为 0：不可走；
- 物件为 1：看地块，地块为 1 才可走；
- 物件为 2：一定可走；
- 不在 `mapset.txt` 里的图号，按原服务端的默认值处理。

## 3. 协议设计原则

- 一条 WebSocket 文本消息 = 一个 JSON 对象，`t` 为消息类型。
- 消息定义只写一份：`proto/messages.json`。`tools/protogen` 由它生成 Go 结构体与分发代码、TS 类型，两端不可能不同步。
- 服务端权威：
  - 客户端只发意图，比如"往方向 d 走一步""说一句话"；
  - 服务端校验后广播结果；
  - 校验失败时回 `PosCorrect`。
- 移动按格子：客户端预测并立即播放走路动画；服务端按节拍校验步频（不快于原版 `walksendinterval`）和通行性。
- 视野：以角色为中心、半径 `VIEW_RADIUS` 格。进出视野时发 `ObjAppear` / `ObjDisappear`，视野内的移动发 `ObjMove`。
- 地图数据：客户端按区块请求 `MapReq` → `MapData`，可以缓存。服务端只发请求范围内的数据。
