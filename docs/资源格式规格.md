# 石器时代客户端资源格式规格

本文描述 `cli/data/` 下图像、调色板、动画资源的**语义**，作为重写客户端时导入器的唯一依据。
内容依据原客户端源码（`cli/石器源码/`）推导，并已对照实际数据文件核验；行为差异或原代码缺陷单独标注。

所有多字节整数均为**小端**。结构体布局按 MSVC 32 位默认对齐（含填充字节），下文给出的偏移即磁盘偏移。

---

## 1. 编号体系（最重要）

客户端里同时存在四种"图号"，混用会导致图像错乱：

| 名称 | 取值范围 | 含义 | 解析方式 |
|---|---|---|---|
| **图像索引** (GraphicIndex) | 0 ~ 约 50 万 | adrn 记录的 `bitmapno`，即 real.bin 中第几张图 | 直接查 adrn 表 |
| **地图图号** (MapNumber) | 1 ~ 约 2 万+ | adrn 记录里 `attr.bmpnumber`，服务器、地图文件、道具图标用的就是它 | 查"图号→索引"表后再查 adrn |
| **动画编号** (SpriteId) | 100000 ~ 139999 | 角色/特效动画，`SpriteId - 100000` 为 spr 表下标 | 查 spr 表 |
| **高彩图号** | ≥ 1000000 | `编号 - 1000000` 为 realtrue/adrntrue 中的索引 | 查 adrntrue 表 |

游戏逻辑拿到一个"角色图号"（`ATR_CHR_NO`）时的解析规则（`pattern.cpp`）：

```
if  编号 <= CG_INVISIBLE           → 不显示
elif 编号 < 100000                  → 地图图号：查表得图像索引，显示单张静态图
elif 编号 < 100000 + 40000          → 动画编号
```

动画帧里的 `BmpNo` **是图像索引**（不是地图图号），也可能是 ≥1000000 的高彩图号。

## 2. adrn（图像索引表）

文件：`adrn_<版本>.bin`。连续的定长记录，每条 **80 字节**，直到文件结束。

| 偏移 | 类型 | 字段 | 语义 |
|---|---|---|---|
| 0 | u32 | bitmapno | 图像索引（作为表的键，**不保证连续、不保证有序**） |
| 4 | u32 | adder | 在 real.bin 中的字节偏移 |
| 8 | u32 | size | 该图在 real.bin 中占用的字节数（含 RD 头） |
| 12 | i32 | xoffset | 绘制锚点偏移 X：屏幕位置 = 逻辑坐标 + xoffset |
| 16 | i32 | yoffset | 绘制锚点偏移 Y |
| 20 | u32 | width | 像素宽 |
| 24 | u32 | height | 像素高 |
| 28 | — | attr | 地图属性，见下表（52 字节） |

**attr（MAP_ATTR，相对偏移，从记录偏移 28 起）**

| 偏移 | 类型 | 字段 | 语义 |
|---|---|---|---|
| 0 | u8 | atari_x | 占地格数 X（东西方向） |
| 1 | u8 | atari_y | 占地格数 Y（南北方向） |
| 2 | u16 | hit | 个位+十位 = 可通行标志（`hit % 100`，0 不可走 / 1 可走）；百位 = 绘制优先级类型（`hit / 100`） |
| 4 | i16 | height | 高度标志 |
| 6..39 | i16 ×17 | broken, indamage, outdamage, inpoison, innumb, inquiet, instone, indark, inconfuse, outpoison, outnumb, outquiet, outstone, outdark, outconfuse, effect1, effect2 | 地块效果（原客户端只用到 `effect1`=环境音效，`effect2`=脚步音效） |
| 40 | u16 ×3 | 保留 | — |
| 46 | — | 填充 2 字节 | — |
| 48 | u32 | bmpnumber | **地图图号**；0 表示没有 |

### 加载时的修正（原客户端硬编码，导入器需复现）

1. 建立"地图图号 → 图像索引"表：对每条 `bmpnumber != 0` 的记录，`表[bmpnumber] = bitmapno`，**后出现的覆盖先出现的**。
2. 跳过规则：`bmpnumber <= 33` 且 `bitmapno > 230000` 的记录不写入图号表（原注释："防止魔法图号覆盖声音"）。
3. 通行修正：`bmpnumber` 在 12802–12811 或 10132–10136 时，`hit = 300 + hit % 100`。
4. 强制可走：图像索引 369715–369847、369941、369641–369654 视为可走（`realGetHitFlag`）。

## 3. real（图像数据）

文件：`real_<版本>.bin`（本数据集约 1.7 GB）。每张图从 `adrn.adder` 开始、长 `adrn.size` 字节，是一个 **RD 块**。

> 偏移量可超过 2 GB，读取时必须用 64 位文件偏移。

### 3.1 RD 块头（16 字节）

| 偏移 | 类型 | 字段 | 语义 |
|---|---|---|---|
| 0 | char[2] | id | 固定 `'R' 'D'` |
| 2 | u8 | compressFlag | 0 = 不压缩；1 = RLE；16 = zlib(RGB565)；17+ = zlib(BGRA8888) |
| 3 | u8 | — | 填充，内容无意义 |
| 4 | u32 | width | 宽 |
| 8 | u32 | height | 高 |
| 12 | u32 | size | **整个 RD 块**长度（含 16 字节头） |

### 3.2 解码规则

**compressFlag = 0**：头后紧跟 `width × height` 字节的原始像素。

**compressFlag = 1（RLE）**：从头后开始，到 `块起点 + size` 为止，逐个读取控制字节 `c`：

| `c` 的位 | 含义 |
|---|---|
| bit7 = 0 | **字面量段**：后面跟 N 个原样像素 |
| bit7 = 1, bit6 = 0 | **重复段**：下一个字节是重复值 V，输出 N 个 V |
| bit7 = 1, bit6 = 1 | **零段**：输出 N 个 0（无值字节） |

长度 N 的编码（对三种段相同，重复段的 V 在长度扩展字节之前）：

| 条件 | N |
|---|---|
| bit5 = 1 | `(c & 0x0F) << 16 \| 下一字节 << 8 \| 再下一字节` |
| 否则 bit4 = 1 | `(c & 0x0F) << 8 \| 下一字节` |
| 否则 | `c & 0x0F` |

> 原解码器对字面量段**只识别 bit4**，不处理 bit5；编码器保证字面量段长度 < 0xFFF，所以实际数据不会出现。导入器按上表统一处理是安全的。
> 原解码器不做越界检查；导入器应在输出达到 `width × height` 时截断。

**compressFlag ≥ 16（zlib）**：头后 `size - 16` 字节为 zlib 流（带 zlib 头），解压后：
- 16：每像素 2 字节 RGB565（小端 u16）。
- 17 及以上：每像素 4 字节，内存顺序 B, G, R, A。

### 3.3 像素语义

| 来源 | 像素 | 透明规则 | 行序 |
|---|---|---|---|
| RLE/原始（8 位） | 调色板下标 | 下标 0 透明 | **自下而上**（第一行是图像最底行） |
| zlib RGB565 | 直接颜色 | 值为 0x0000 的像素透明 | 自下而上 |
| zlib BGRA8888 | 直接颜色 + alpha | A = 0 透明，其余按 A 混合 | 自下而上 |

8 位图使用**全局调色板**（第 4 节），该调色板会随时间切换（昼夜），因此 8 位图**不应在导入时烘焙成 RGBA**，应保留下标，运行时用调色板纹理查色（见第 8 节）。

### 3.4 原数据中的已知缺陷（导入器必须容忍）

- **不压缩块的 size 字段无效**：原编码器在 compressFlag=0 时把一个内存指针写进了 size。读取时以 adrn.size 为准。
- **RLE 多出 1 个像素**：少数图（本数据集 289 张）的 RLE 流解出 `w×h+1` 个像素。原解码器不检查边界，多写的 1 字节落在缓冲区余量里。导入器在填满 `w×h` 后截断即可。
- **尺寸为负的记录**：4 张图（索引 8614、8619、322863、344133）在 adrn 和 RD 头里的高度都是负数。原客户端不会绘制它们，导入器按空图处理。
- **行宽补齐**：原客户端在绘制 8 位图前会把行宽向上补齐到 4 的倍数（`sprmgr.cpp`），但解码缓冲本身不补齐。本数据集中所有图宽都是 4 的倍数，这条规则不起作用；如果别的数据集出现非 4 倍数宽度，需要用实际数据确认原客户端是否会错位。

## 4. 调色板

### 4.1 组成（256 色）

| 下标 | 来源 |
|---|---|
| 0–9 | 固定系统色（见下） |
| 10–15 | 固定扩展色 |
| 16–239 | 从 `.sap` 文件读取，可切换 |
| 240–245 | 固定扩展色 |
| 246–255 | 固定系统色 |

固定色（R, G, B）：

```
0:(00,00,00) 1:(80,00,00) 2:(00,80,00) 3:(80,80,00) 4:(00,00,80)
5:(80,00,80) 6:(00,80,80) 7:(c0,c0,c0) 8:(c0,dc,c0) 9:(a6,ca,f0)
10:(de,00,00) 11:(ff,5f,00) 12:(ff,ff,a0) 13:(00,5f,d2) 14:(50,d2,ff) 15:(28,e1,28)
240:(f5,c3,96) 241:(e1,a0,5f) 242:(c3,7d,46) 243:(9b,55,1e) 244:(46,41,37) 245:(28,23,1e)
246:(ff,fb,f0) 247:(a0,a0,a4) 248:(80,80,80) 249:(ff,00,00) 250:(00,ff,00)
251:(ff,ff,00) 252:(00,00,ff) 253:(ff,00,ff) 254:(00,ff,ff) 255:(ff,ff,ff)
```

### 4.2 .sap 文件

`data/pal/Palet_N.sap`，708 字节。前 672 字节为 224 组 **B, G, R** 三元组，依次填入下标 16–239；其余字节不使用。

下标 168 被强制设为黑色 (0,0,0)（转生特效期间除外）。

### 4.3 编号与切换

调色板编号 0–14 对应 `Palet_1.sap` … `Palet_15.sap`，15 对应 `Palet_0.sap`（开场 logo）。
服务器下发切换指令后，原客户端在 `time` 帧内对下标 16–239 做**线性插值**过渡到新调色板。

## 5. 高彩图（realtrue / adrntrue）

### 5.1 adrntrue（每条 40 字节）

| 偏移 | 类型 | 字段 | 语义 |
|---|---|---|---|
| 0 | u32 | bitmapno | 高彩索引（游戏中引用时加 1000000） |
| 4 | u32 | adder | 在 realtrue 中的偏移 |
| 8 | u32 | palSize | 局部调色板字节数 **减 4** |
| 12 | u32 | size | RD 块长度 |
| 16 | u32 | alpha_size | alpha 的 RD 块长度；0 表示无 alpha |
| 20 | i32 | xoffset | 锚点 X |
| 24 | i32 | yoffset | 锚点 Y |
| 28 | u32 | width | 宽 |
| 32 | u32 | height | 高 |
| 36 | u32 | staturated | 是否使用饱和（加色）混合 |

### 5.2 realtrue 中一张图的布局

```
adder → [局部调色板 palSize+4 字节，RGBQUAD 数组：B,G,R,0]
        [像素 RD 块 size 字节，解出 8 位下标，查局部调色板]
        [alpha RD 块 alpha_size 字节（可选），解出每像素 8 位 alpha]
```

- 行序：**自上而下**（与 real.bin 相反）。
- 透明：没有 alpha 块时，颜色转成 RGB565 后为 0 的像素（即近黑色）透明；有 alpha 块时以 alpha 为准。

## 6. 动画（spr / spradrn）

### 6.1 spradrn（每条 12 字节）

| 偏移 | 类型 | 字段 | 语义 |
|---|---|---|---|
| 0 | u32 | sprNo | 动画编号（≥100000） |
| 4 | u32 | offset | 在 spr.bin 中的偏移 |
| 8 | u16 | animSize | 动作条目数（动作种类 × 方向） |
| 10 | — | 填充 | — |

### 6.2 spr.bin

从 `offset` 起连续 `animSize` 个动作条目，每个条目：

```
动作头 12 字节：
  u16 dir        方向 0–7
  u16 no         动作类型（见下表）
  u32 dtAnim     整个动作一次循环的时长（毫秒级单位）
  u32 frameCnt   帧数
接着 frameCnt 个帧，每帧 10 字节（无填充）：
  u32 BmpNo      图像索引（或 ≥1000000 的高彩图号）
  i16 PosX       帧偏移 X
  i16 PosY       帧偏移 Y
  u16 SoundNo    帧事件
```

动作类型 `no`：0 攻击，1 受伤，2 死亡，3 站立，4 行走，5 坐下，6 挥手，7 高兴，8 生气，9 伤心，10 防御，11 点头，12 投掷。

### 6.3 播放语义

- **选择条目**：按 (方向, 动作类型) 精确匹配；找不到时退回同方向的"站立"；再找不到用第 0 条。
- **帧时长**：原客户端把 `dtAnim / frameCnt / 16`（整数除法）作为每帧停留的逻辑帧数。按设计帧率 60 fps（约 16 ms/帧）换算，**每帧时长 ≈ dtAnim / frameCnt 毫秒**。调用方可以指定速度覆盖该值（战斗中常用）。
  - 结果为 0 时（本数据集 616 个条目，几乎都是"受伤"动作），原客户端的计时器会减成负数，**动画停在首帧**，除非调用方指定了速度。新客户端可以选择复现，或者按 1 个逻辑帧处理。
- **空帧**：`BmpNo = 0xFFFFFFFF` 表示该帧不绘制，但照常计时、照常触发帧事件。本数据集有 4756 个空帧。原客户端加载补丁包时对空帧也加了偏移，溢出后会变成一个有效图号、显示出错误的图；导入器不对空帧加偏移。
- **绘制位置**：`屏幕坐标 = 角色坐标 + 帧.PosX/PosY + 该图的 adrn.xoffset/yoffset`。
- **帧事件 SoundNo**：
  - 0：无
  - 1–9999：播放音效编号 SoundNo
  - 10000–10099：伤害数字/命中效果触发点
  - ≥10100：连击触发点
- **循环**：播放到末尾后，循环模式回到第 0 帧，非循环模式停在结束状态并通知调用方。

### 6.4 加载后的硬编码修正

原客户端在加载后对部分动画做了数据修补（`loadsprbin.cpp`），导入器需复现，例如 1059 号第 80 条第 8 帧改为图 283639、502 号被重建为 3 帧（图 8590–8592）、382 号由 381 号派生出 14 帧序列等。完整列表在 `SprFixups.cs` 中逐条实现。
（这里的"N 号"指 `sprNo - 100000`。）

## 7. 补丁包（分离 bin）

原客户端启动时递归扫描 `./path/` 下的子目录，每个目录可包含：

```
adrn.es  real.es  spradrn.es  spr.es
```

- `adrn.es` 经过 **XXTEA 解密**：以 32 位小端字为单位，全文件作为一个块，密钥为 ASCII 字符串 `554CDB1A99DF514B` 的 16 字节（解释为 4 个小端 u32）。
- 每个补丁包的图像索引在原值上**加上之前已加载的最大图像索引**（`MaxAdrnID`），图号表同样指向偏移后的索引。
- 该补丁包的 spr 中所有帧的 `BmpNo` 加上**本包加载前**的 `MaxAdrnID`。
- 补丁包按目录枚举顺序加载，最多 99 个。

本数据集当前没有 `path` 目录，但导入器应支持。

## 10. 网页导出格式（WebExporter，格式版本 1）

由 `tools/WebExport` 生成，供 HTML5 客户端按需加载。所有坐标单位为像素，Y 轴向下。

### 10.1 目录结构

```
manifest.json          格式版本、页尺寸、页数、图像清单分块列表
palettes.png           256×16 RGBA；第 N 行 = 调色板编号 N；下标 0 的 alpha 为 0
tiles.json             地图图号表与地块属性
images/NNNN.json       图像清单，文件号 = 图号 >> 12（每块 4096 个编号）
pages/i8/NNNNN.<ext>   8 位图集页：灰度值 = 调色板下标，0 = 透明
pages/rgba/NNNNN.<ext> 高彩图集页：RGBA，未预乘
anim/<动画编号>.json    每个动画一个文件
audio/bgm/*.ogg        背景音乐（Ogg Opus），文件名与原 wav 相同
audio/se/*.ogg         音效（Ogg Opus）
audio/index.json       {"bgm": {文件名: 时长毫秒}, "se": {...}}
```

图集页扩展名由 `manifest.pageFormat` 给出：`png`（默认）或 `webp`（无损，用 `--cwebp` 导出）。
WebP 解码后 8 位页的 R=G=B=下标、A=255，与灰度 PNG 读法相同。

### 10.2 图像清单 `images/NNNN.json`

```json
{"base": 4096, "img": [[集合, 页, x, y, w, h, 锚点x, 锚点y, 原宽, 原高], 0, ...]}
```

- `img[i]` 对应图号 `base + i`；`0` 表示该编号不存在。
- 集合：0 = `pages/i8`，1 = `pages/rgba`。页为 -1 表示整张图透明，不需要绘制。
- 图已裁掉透明边，`(x, y, w, h)` 是裁剪后在图集页中的位置。
- 锚点已包含裁剪偏移：**屏幕位置 = 逻辑坐标 + (锚点x, 锚点y)**，直接画 `w×h` 即可。
- 原宽、原高是裁剪前的尺寸，供点击判定等需要原始矩形的逻辑使用。
- 高彩图号（≥1000000）使用同一套分块规则。

### 10.3 动画 `anim/<编号>.json`

```json
{"id": 100000,
 "actions": [{"dir": 0, "type": 4, "ticks": 8, "freeze": 1,
              "frames": [[图号, 偏移x, 偏移y, 事件], ...]}],
 "pages": ["i8/98", "i8/99"]}
```

- `ticks`：每帧停留的逻辑帧数（规格 6.3），按 60 fps 换算时长。
- `freeze`：只在原客户端会停在首帧时出现（规格 6.3）。
- 图号为 -1 表示空帧。
- 绘制位置 = 角色坐标 + 帧偏移 + 图像清单里的锚点。
- `pages`：播放这个动画需要的全部图集页，用于预加载。

### 10.4 地图图号表 `tiles.json`

```json
{"forcedWalkable": [[369715, 369847], [369941, 369941], [369641, 369654]],
 "tiles": [[地图图号, 图像索引, 占地x, 占地y, hit, 高度, 环境音效, 脚步音效], ...]}
```

`forcedWalkable` 是按图像索引强制可走的闭区间（规格 2）。

### 10.5 浏览器端注意事项

- 加载图集页时必须关闭色彩空间转换和预乘，否则下标会被改掉：
  `createImageBitmap(blob, {colorSpaceConversion: "none", premultiplyAlpha: "none"})`，
  并设置 `UNPACK_COLORSPACE_CONVERSION_WEBGL = NONE`、`UNPACK_PREMULTIPLY_ALPHA_WEBGL = false`。
- 8 位页上传为 `R8UI` 纹理，shader 用 `texelFetch` 取下标，再从 `palettes.png` 查色；昼夜过渡 = 对两行调色板做插值。
- 采样一律用最近邻（像素画）。每张图四周留了 1 像素透明间隙。
- 参考实现：`tools/web-viewer/index.html`。

### 10.7 图集页压缩方案对比

样本：均匀抽取 50 张 8 位页、15 张高彩页，32 并发。

| 方案 | 8 位页 | 高彩页 | 耗时 |
|---|---|---|---|
| 自带 PNG 编码器（基线） | 9.54 MB | 4.82 MB | — |
| oxipng `-o 4` | 8.84 MB（−7%） | 3.44 MB（−29%） | 3.4 s |
| oxipng `-o max` | 8.84 MB | 3.43 MB | 13 s |
| oxipng `-o max -Z`（zopfli） | 8.86 MB | 3.41 MB | 206 s |
| 无损 WebP `-z 6` | 8.64 MB（−9%） | 2.63 MB（−45%） | 1.7 s |
| **无损 WebP `-z 9`（采用）** | **8.37 MB（−12%）** | **2.08 MB（−57%）** | 17 s |

**试过但无效**：
- 8 位页做 PNG 行滤波：969 MB → 1194 MB，下标值不连续，差分反而有害。
- 按调色板亮度给下标重新排序（让相近颜色的下标也相近）：PNG 969 → 967 MB；WebP 和 oxipng 结果不变。两者遇到不超过 256 色的图会自动转成调色板模式，下标顺序不影响结果。
- 8 位页压缩空间小的根本原因：像素本身就是调色板下标，信息量已经接近下限。

无损 WebP 的浏览器要求：Chrome 32+、Firefox 65+、Safari 14+（macOS 11 / iOS 14 起）。

### 10.8 音频

| 来源 | 原始 | Ogg Opus | 码率 |
|---|---|---|---|
| `data/bgm/*.wav`（26 个，8 位立体声 22050 Hz） | 84.5 MB | 14.7 MB | 64 kbps |
| `data/se/*.wav`（194 个，8 位单声道 22050 Hz） | 8.9 MB | 1.2 MB | 32 kbps |

- 码率对比：背景音乐 48/64/96 kbps 分别为 11.1/14.7/22.0 MB；音效 24/32/48 kbps 分别为 0.9/1.2/1.8 MB。采用的是偏保守的码率，**没有经过人耳试听**。
- 浏览器（Chromium）中用 `decodeAudioData` 解码全部 220 个文件，时长与原 wav 相差不超过 1 ms（时长表取整误差），尾部没有填充静音，背景音乐可以无缝循环。
- `data/sound_3.bin`（2.6 MB）是 `se/saam_*.wav` 打成的包，同一批 27 个文件存了 3 份，原客户端没有引用它，不转换。
- Safari 对 Ogg Opus 的支持取决于版本，没有测试。如果要覆盖较老的 iOS，需要另出一份 AAC（.m4a）作为备用。

**仍可继续的方向**（没有实测）：
- 按动画重新分组装箱，减少一个动画跨的页数，代价是共享帧会重复存储。
- 地图地块按楼层分组。这需要服务端的地图数据，客户端数据里没有。
